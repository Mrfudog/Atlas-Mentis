## Übernahme dev → prod: ein Befehl

Gebaut ist `scripts/uebernahme-ebenen.mjs`. Es spricht nur mit dev, dev spricht über die Werkbank-Übernahme (T-130) mit prod.

```sh
# Probelauf: zählt je Ebene neu / geändert / unverändert / Konflikt / nur prod und die Verlustliste, schreibt nichts
node scripts/uebernahme-ebenen.mjs --out uebernahme-probe.json
# Lauf: schreibt je Ebene nur, was auf prod neu ist; eine Ebene mit nicht leerer Verlustliste wird ausgelassen
node scripts/uebernahme-ebenen.mjs --run --out uebernahme-lauf.json
```

Voraussetzungen (docs/Betrieb.md › Übernahme dev ↔ prod › Einrichten):

1. Token eines Kontos mit **Verwaltung** auf dev (`ATLAS_DEV_TOKEN` oder Network secret). Das Konto `claude` reicht nicht
   (403 „Die Übernahme ist Sache der Verwaltung.“).
2. prod: `ATLAS_TRANSFER_ACCEPT=1` in `/srv/atlas/prod/.env`, dazu ein `write`-Token der Verwaltung von prod.
3. dev: `ATLAS_PEER_URL=https://ttrpg.fuchsbau.io` und `ATLAS_PEER_TOKEN=atm_…` in `/srv/atlas/dev/.env`, beide neu ausrollen.
4. Danach die Zeilen wieder herausnehmen (E-042).

**Erwartung für den Probelauf:** prod hat am 13.10. mit dem Importer von damals 5e.tools eingelesen (`replace-layer`, Lauf
38394474352). Dieselben Artikel stehen also auf beiden Seiten, aber ohne gemeinsame Basis. Die Übernahme zeigt sie darum als
**Konflikt** (docs/Betrieb.md: „einen Konflikt je Feld, weil es noch keine Basis gibt“). Das Skript schreibt keine Ebene mit
Konflikten. Für diese Ebenen entscheidet die Leitung (Entscheid im Brett): „dev nehmen“ in der Werkbank für die 5e.tools-Ebenen,
weil auf prod niemand 5e.tools-Artikel pflegt. Kampagnen- und Spielerebenen sind nicht in der Liste und werden nicht angefasst.

**Nicht gehen:** die Pipeline mit `only-new` nach prod. Der Bestand dort stammt aus einem älteren Importer, und `only-new`
legte geteilte Aktionen und Merkmale ein zweites Mal an (wie am 14.10. auf dev).

**Zählung nachher:** dieselbe Tabelle wie oben, auf prod. Der Probelauf auf dev ist der Prüfbericht. Nach dem Lauf muss
`node scripts/uebernahme-ebenen.mjs` (wieder Probelauf) für jede Ebene `neu 0 · Konflikt 0` sagen, und die Verlustliste
muss leer sein.
