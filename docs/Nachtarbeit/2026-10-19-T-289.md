# Karten im Spiel auf dev (T-289)

19.10.2026, Sitzung https://claude.ai/code/session_0136s5Ek4VV8uZmtm5bTDUqr

## Warum

Die Leitung (19.10., E-039, E-041): „Beim Nutzen soll eine Instanz der
Karte/des Encounters erstellt werden.“ Spiel-Tokens und Nebel stehen seit
T-289 an der Instanz, nicht an der Karte. Was heute an Karten liegt, zieht
die Migration `106_karten_im_spiel.sql` beim nächsten Start nach — von Hand
wird auf dev nichts geändert.

## Was (gelesen am 19.10. gegen dev, vor dem Ausrollen)

Die Migration legt je Karte mit Spiel-Tokens oder als „Map on the table“
einer Sitzung eine Instanz `mi_<karte>` an — freigegeben, in den Ebenen
der Karte, mit ihrem Nebel — und zieht Tokens, Aufgedecktes und den
Verweis der Sitzung dorthin. Auf dev betrifft das zwei Karten in
„basil · Tests“:

| Karte | Was heute dran ist | Danach |
|---|---|---|
| Turn planner test map (`map-0898`, `e_7c319e27d71d`) | 2 Spiel-Tokens (Turn planner test hero, Goblin), 5 aufgedeckte Formen | Instanz `mi_e_7c319e27d71d` trägt beides; die Karte behält ihre übrigen Marker, keinen Nebelstand |
| Sewer Hideout (`map-0897`, `e_2bea55e74a44`) | „Map on the table“ der Sitzung „Test 0“ (`session-0001`) | Instanz `mi_e_2bea55e74a44`; die Sitzung zeigt auf sie |

Der Start schreibt je Instanz eine Zeile ins Log
(`T-289: <Karte> (<id>) → Instanz …`).

## Zurück

Die Instanz löschen und die Tokens an die Karte zurücksetzen geht über
eine Massenänderung; einfacher: die Sicherung vor dem Ausrollen
(docs/Betrieb.md › Sichern und zurück).
