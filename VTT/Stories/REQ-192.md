# REQ-192 Gleichzeitig bearbeiten ohne Verlust

**Als** Spielleitung **möchte ich** dass bei zwei gleichzeitigen Bearbeitungen die zweite nicht still gewinnt, sondern zusammengeführt wird, **damit** keine Änderung verloren geht.

## Akzeptanzkriterien

- Jeder Artikel trägt eine Revision; ein veralteter Stand wird abgelehnt (409).
- Die Maske bietet das Zusammenführen an.

## Anmerkungen

REQ-116 covers realtime session state; ordinary two-device editing is unspecified — Stand: Prototyp; Server ohne Revisionsprüfung

**Rollen am Konto (T-452, 4.11.2026):** auch die Rolle eines Kontos je Kampagne darf bei zwei gleichzeitigen Änderungen nicht verloren gehen. Die Mitgliederrouten und `user role` schreiben seither eine Zeile je (Konto, Kampagne) (`Repository.setRole`), statt das Konto zu lesen und ganz zurückzuschreiben; `putUser` nimmt Rollen nur beim Anlegen mit. Geprüft mit zwei verschränkten Änderungen (`apps/server/test/rollen-gleichzeitig.test.ts`) und im Durchstich gegen Postgres. Offen bleibt dasselbe Muster für die Figurenzuteilung (`app_user_actor`), siehe Brett.

```mermaid
sequenceDiagram
    participant A as Route A (Kampagne A)
    participant B as Route B (Kampagne B)
    participant DB as campaign_member
    A->>DB: setRole(konto, A, gm) — eine Zeile
    B->>DB: setRole(konto, B, gm) — eine andere Zeile
    Note over DB: beide Zeilen stehen; keine Route liest oder schreibt die andere
```
