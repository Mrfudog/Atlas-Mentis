# REQ-182 Kanten lesen sich von beiden Enden

**Als** Spielleitung **möchte ich** dass eine Kante an beiden Enden passend beschriftet ist (z. B. „member of“ und „members“), **damit** eine einmal gespeicherte Verbindung von beiden Seiten verständlich ist.

## Akzeptanzkriterien

- Die Kantenart trägt eine Beschriftung für die Gegenrichtung (`inverseLabel`).
- Gespeichert wird die Kante nur einmal, die Gegenrichtung ist eine Abfrage.

## Anmerkungen

Schema gap in `meta/relation`. Gläubiger ↔ Schuldner, Anführer ↔ Untergebene/r. Cheap now, painful once data exists — Stand: `inverseLabel`

## Bisheriger Wortlaut

> Relation inverse labels in `relation_def`, so one stored edge renders correctly from both ends
