# REQ-287 Regelsysteme und Module als Ebenen

**Als** Spielleitung **möchte ich** dass ein Regelsystem (z. B. D&D) und seine Module (Inventar, Handwerk, Reise …) Ebenen sind, aus denen die Kampagne je Sorte ein Modul wählt, **damit** eine Runde ihre Regeln zusammenstellt, ohne dass Code sie kennt.

## Akzeptanzkriterien

- Regelsysteme und Module sind Ebenen (E-078); ein Modul gehört zu einer Sorte und kann in mehreren Systemen stecken.
- Ein Modul bringt eigene Methoden mit: wie es zählt, was es zeigt, was es sperrt (E-090–E-094).
- Je Sorte gilt genau ein Modul; die Leitung wählt es an der Kampagne.
- Eine Regelmechanik sagt, mit welchen anderen sie zusammen gilt (`compatibleWith`, z. B. Grid mit Weight); was nicht so verbunden ist, schliesst sich innerhalb eines Regelsystems aus (E-166).
- Ein tieferes Modul, das durch die Wahl ausgeschlossen ist, wird nicht angezeigt — weder seine Felder noch seine Knöpfe.
- Reines D&D heisst beim Inventar: Gewicht, ohne Raster.
- Inventar, Handwerk und die übrigen Teilsysteme lesen die Wahl der Kampagne über eine Funktion je Sorte.

## Anmerkungen

Entscheide der Leitung vom 16.10.2026: E-078 (Module als Ebenen), E-090–E-094 (Methoden, ein Modul je Sorte, Wahl an der Kampagne, Ausschluss, D&D-Vorgabe). Sie präzisieren E-044 c: ein Modul ist eine Ebene, kein Artikel in einer Ebene. Abwägung: `docs/Regelsysteme.md`.
22.10.2026 (E-166): Ein Regelsystem (Inventory) ist eine Ebene der Art `RuleSystem`, seine Optionen (Grid, Weight, Slots, Default shapes) sind Ebenen der Art `RuleMechanic` und geben an, mit welchen sie kompatibel sind.
